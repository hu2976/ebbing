参赛规划

退潮 · 第六份文档 · 2026-08-24 · 目标：过初评摆摊，进决赛

已定：命题选 eazo · 个人参赛 · 可带已有项目 · 仓库全推不脱敏

这份文档只回答一个问题：手上这些东西，怎么排才能过摆摊那一关。
排序依据是评分表的权重乘缺口大小，不是兴趣。

01三个战略判断

一 · 滋味墙从「要不要做」变成「不做就丢 20 分」

评分表里技术能力占 20%，创作导向明写「不鼓励功能堆砌或仅做界面演示」。

现在的退潮是纯前端 + localStorage 的 36 屏，技术能力这一项接近零分，而且正好撞在那句禁令上。朋友说的「小儿科」和这 20 分是同一件事。

滋味墙的价值已经不是立意。
它是唯一能把作品从「界面演示」变成「有后端、有判定、有 AI 原生架构」的东西。

二 · 企业命题选 eazo

eazo「她创所爱 · 为你而造」的原文是「把『她每天经历的事』，做成一个以前没人替她做过的 App」。这就是退潮的定义——零改动契合，额外奖金，没有不选的理由。

沙利文的 PROOF OF INSIGHT 和食物库契合度确实高（证据链、结论验证器）。但选它等于换回已废方向（不回扣女性、立意不深刻），而且贴纸看起来只能贴一张。

但它的语言要偷

沙利文命题的核心主张和滋味墙的技术立场是同一句话：

沙利文：「AI 生成的内容不应自动成为事实或最终结论」、「人对最终判断负责」
我们：「让 AI 判语言，不让 AI 写内容」

写「创新点」那一章直接用这套话。评委席上若有沙利文的人，这段是白送的。

三 · 摆摊不是劣势，是礼物

台上路演三分钟，墙是空的。摆摊是一整天，墙会一直长。

一天下来墙上是几百个陌生人现场写的真句子。这是任何界面演示都做不出来的东西，而且它一次性喂饱三项：完成度、现场演示、后续发展潜力。评委第二次路过时看到墙比第一次满——这个体验强过任何讲解。

推翻前一版的 demo 设计

此前设计的「全场扫码现场写」是决赛台上的高潮，初评摆摊用不上（没有「全场」）。摆摊场景下评委一次可能只给 60 秒，摊位设计的目标不是讲清楚，是让人不用听讲就懂。见 06 节。

02评分表逐项对账

软件赛道初审七项，逐项算缺口。红＝硬缺口，绿＝已经是强项。

维度权重现状怎么补 / 拿什么证明
创新性20%立意新，但摊位上看不出来「准入门槛就是治疗」＋「让 AI 判语言不让 AI 写内容」，两句都能 30 秒讲完
技术能力20%接近零——纯前端文案屏三层判定器 ＋ 云开发 ＋ 多 agent 分条判定
完成度15%高：36 屏、自检基线（屏 36／块 371／零死链）、两端一屏装下全达标把 chk.mjs／shot.mjs 的自检写进项目文档，这是完成度的硬证据
问题洞察与价值15%最强项：病理 ＋ 30 竞品地形 ＋ 数据底册摊位要有 30 秒能讲完的版本，别让它烂在文档里
展示表达与团队协作10%个人参赛，协作分天然吃亏见 07 节：用真实迭代记录补
后续发展潜力10%原来一般墙会长＝天然增长故事；「后续计划」章写清墙满了之后是什么
现场演示10%现在是翻页路人动手 ＋ 墙在长 ＋ 故意演示一次被退回
唯一的硬缺口是技术能力那 20%，而滋味墙正好补它。
其余六项要么已经强，要么靠文档和摊位布置就能拿。

03提交清单：准入，不是加分

这些东西不加一分，但缺一样就交不上。所以优先级高于一切加分项。

要交的状态做法
选择的赛道及命题已定软件应用赛道「滴水穿石」＋ eazo「她创所爱·为你而造」。命题贴纸记得贴摊位。
作品名称已有退潮
作品 Slogan待定见 05 节，候选已挑好
作品描述待写见 05 节
项目图片待做一堵食物颜色的墙的截图。这是全项目最有冲击力的一张图。
GitHub 仓库 ＋ Tag #shenicest-fission没有工程现在在 Desktop，零 git。已决定全推、不脱敏，所以直接建、直接推，不用做剔除。Tag 别忘。
项目文档素材足，需重组七项：背景／目标用户／技术栈／创新点／团队分工／开发过程／后续计划。素材全在 01、03、05、10、11 五份文档里，是重组不是新写。
作品演示视频没有见 05 节脚本。必须在滋味墙跑起来之后拍，否则视频里没有新功能。
可体验链接（可选）半有体验版二维码。摆摊要用，所以实际上不是可选。⚠️ 体验成员上限只有 15 个（08-26 后台实测）——扫码那条路撑不起一整天，主力必须是自己带的设备。

04三批活与顺序

依赖关系只有一条硬的：演示视频要等滋味墙能跑。其余可并行。

批 A · 准入（不做就交不上）

A1
建 GitHub 仓库、推现有工程、打 Tag #shenicest-fission
第一件做，因为后面每天都在往里推。仓库先建空的也行。
A2
项目文档按七项重组
重组不是新写。「开发过程」那一项是你的隐藏强项，见 07 节。
A3
名称 / Slogan / 描述 / 项目图片
图片等墙有内容之后截，所以排在批 B 后面。
A4
演示视频
依赖批 B。脚本见 05 节。

批 B · 补技术能力那 20 分（滋味墙最小可跑版）

B1
云开发初始化 ＋ cards 集合
工程现在零云开发痕迹。food／desc／createdAt／status，不存任何用户标识。顺手把「在场人数」那笔欠账一起还。
B2
写入 ＋ 读墙，接到现有 wallDay
读墙走数据库权限「所有人可读」＋前端直连，不走云函数（省调用省延迟）。
B3
L1 硬规则（纯 JS，零成本）
长度／数字／评价词／欲望词／健康与否／有标记比喻／裸食物名不过。CLIN 表直接复用 chk.mjs，不新建第二份清单。
B4
security.msgSecCheck——这条归在批 A 的强度，不可砍
汪曾祺六条挡不住违法内容，也挡不住有人把催吐方法写成「味道」的样子投进墙里。命中时不告诉用户原因，否则等于教人绕过。
B5
L2 食物库挡编造
可降级：先用一张几百条的高频食物名单，不接全库。摊位上看不出差别。
B6
L3 多 agent 分条判语义
一个只判比喻、一个只判主语、一个只判评点、一个只判有没有手上的动作。六条塞一个 prompt 准确率会塌——分开判本来就更准，同时正好命中「AI 原生应用、Agent 协同」这条加分导向。

批 C · 摆摊

C1
摊位屏：一直显示墙，实时长
C2
桌上一张纸：汪曾祺六条
路人读这张纸才去写卡——读规则本身就是产品的核心动作。摊位的物理布置直接演示了产品机制，这是台上做不到的事。
C3
三个长度的说法：15 秒 / 60 秒 / 3 分钟
摆摊最贵的资源是评委的注意力，不同人给的时间差 10 倍。

05Slogan、描述、视频脚本

Slogan

我们让她重新拥有形容词。
不许提数字的食物墙。
所有产品都在给她更准的数字。

推第一条：一句话讲完产品，不含任何临床词，且那个「她」正好接住 eazo 命题。

作品描述（三句结构）

1 · 问题  进食障碍不是失控，是掌控用错了地方。她们不缺数字——
          她们对食物的语言只剩下数字，说不出「香」，只能说「多少卡」。

2 · 做法  一堵所有人写的食物滋味墙。想在墙上写一张卡，
          得先通过一道门槛：不许比喻、不许评点、不许提数字、
          必须有一个手上的动作。

3 · 创新  门槛不是在挡人，是在教一种说话方式——
          而「不评价食物」练熟了，就是「不评价自己」。
          判定全部由规则和食物库完成，AI 只判语言，不写内容。

演示视频（60–90 秒）

  1. 控诉（约 10 秒）：所有产品都在给她更准的数字。
  2. 墙（约 15 秒）：一堵在长的、由食物颜色铺成的墙。不讲解，就看。
  3. 写一张卡（约 30 秒）：写一句带比喻的 → 被退回，屏上说「这是个比喻」 → 改 → 上墙。
    这 30 秒同时证明门槛是真的、判定是真的、产品在教一种说话方式。全片最重要的一段。
  4. Slogan（约 5 秒）。

06摊位怎么摆

摆摊和台上路演是两种不同的东西。台上是你控制节奏，摆摊是评委控制节奏，而且随时可能走。

给你多少时间说什么
15 秒
路过型		「这是一堵所有人写的食物滋味墙。想写上墙，你得先学会不评价食物。」
说完就指屏幕。让墙自己说。
60 秒
停下来型		加两件事：① 病理一句（不是失控，是掌控用错了地方）；② 请他现场写一句——最好被退回一次。
3 分钟
评委细问型		加技术（三层判定 ＋ 多 agent 分条判 ＋「AI 判语言不写内容」及其证据）、竞品地形（急性期入口已被占，做的人都停在冲动退下去为止；躯体层整个品类空白）、后续计划。
摊位上最值钱的一件事

让评委自己被退回一次。他写一句「像丝绸一样滑」，屏上回「这是个比喻」——那一秒他同时明白了三件事，而且是他自己发现的，不是你讲的。
自己发现的结论没法反驳。

07一个人怎么拿「团队协作」那 10%

诚实写个人，然后把分数从「开发过程」那一栏挣回来。这一项恰好是你的隐藏强项——大部分参赛者的「开发过程」只能写「三天写完」，而你有真实的、可查的迭代记录：

  • 26 屏文案的定稿过程：那把尺子（念出来，不会对着坐在旁边的人这么说，它就是机械的）＋ 五处抽象词的具体改法与理由
  • 字体走过三版：网络字体不下载→深色底宋体像悬疑片字幕→同族苹方靠字重分层
  • 情绪瓶子从 CSS 关键帧改到 canvas ＋ PBD 物理，含「出生点必须在罐内」那个 bug 的根因（速度回写把瞬移当一帧走完 → vy 炸到四倍）
  • shot.mjs 的 TOP 算错 47px，导致一批「测出来装下」的屏在真机上是超的
  • 食物库分类体系 12 轮交叉审查、微量营养素规范 7 轮
  • 选题本身被推翻八次，每次的否决理由都留了档（05 节第 03 章）
个人完成 36 屏 ＋ 后端 ＋ 判定器，本身就是技术能力的证据。
而「被推翻八次还留着每次的否决理由」是一种没法编的东西。

08时间不够时按这个顺序砍

提前定好砍单顺序，现场就不用临时判断。从上往下砍。

先砍
L3 多 agent 语义判定 → 门槛松一档，墙照样立得起来。代价：损失「AI 原生 / Agent 协同」那部分加分，摊位上讲架构时改讲「已设计、未接入」。
再砍
L2 接全食物库 → 降级成几百条高频食物名单。代价：摊位上看不出差别。
再砍
墙的新视觉 → 直接用现有 cardHue 出，不做新样式。
再砍
照护者端的新增内容 → 保持现状，一个字不动。
绝不砍
  • security.msgSecCheck——安全，且这是唯一挡有害内容的东西
  • 写入 ＋ 读墙——砍了就没有滋味墙，技术那 20 分回到零
  • GitHub 仓库 ＋ Tag、演示视频、项目文档——准入项，缺一样就交不上
  • 36 屏文案——一个字不改，体验版不过审是前提

09要你去确认的四件事

  1. 比赛具体日期，以及提交截止是现场结束前还是之后。这份文档按「批 A 可先做、批 B 现场推进」排，日期定了才能落到天。
  2. 命题贴纸能贴几张。如果能贴两张，沙利文那个值得再算一次——食物库那条线可以在「创新点」里当第二命题的答卷。
  3. 摊位有没有电、能不能带自己的屏。C1 整条依赖这个；不能带屏就得改成手机递给评委看，效果差一档，得提前想。
  4. 08-26 已确认：体验成员上限 15 个，不是 100。所以现场人数多少都不改变结论：主力是自己带的两台设备，递给评委用；二维码只留给真想深入的人当场加（加一个要输微信号、对方还得同意，一天最多十几个）。
