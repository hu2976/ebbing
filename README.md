# 退潮 · ebbing

> 我们让她重新拥有形容词。

面向**进食障碍全谱系**（暴食 / 厌食 / 贪食）患者及照护者的**匿名自助**微信小程序。无账号、无登录、数据不出设备。

**赛道**：软件应用赛道 · 滴水穿石　|　**命题**：eazo「她创所爱 · 为你而造」

---

## 这个产品在解什么

进食障碍不是失控，**是掌控用错了地方**。她们不缺自律——自律是全场最强的，问题是它指向了「少吃」。掌控欲消灭不了，也不该劝人放手（劝就是评价），只能改道。

一个人对食物的语言只剩下数字。她说不出「香」，只能说「多少卡」。所有产品都在给她更准的数字。

## 三件别人没做的事

### 一 · 我写的滋味

每天一张滋味卡。她可以从**色 / 香 / 味 / 声 / 质地**五个角度写下自己记得的样子，写完之后，卡面上系统那段话被换成她自己的话。用久了，整本卡都是她写的。

> **这个产品最后会把自己说的话，全部还给你。**

门槛不是正能量过滤器，是**「描述 vs 判断」过滤器**：

| 她写 | 结果 | 屏上那句 |
|---|---|---|
| 恶心 | 不进公共池 | 「这是判断，不是味道。」 |
| 像屎一样 | 不进公共池 | 「这是个比喻。」 |
| **入口即化** | **同样不进** | 理由和「恶心」一模一样 |
| **臭 / 酸了 / 发苦 / 黏手** | **放行** | 那是真实的气味 |

规则对称，不偏向好话。**我们不要求她说好话，只要求她说的是味道。**

而**存下来、上时间线、上卡面是三个不同的权限**：她写什么都存（永远在她自己手机里），时间线里全都在（变化要看得见），卡面只放过了门槛的那条（那张卡她每天会再看到一次）。**产品从头到尾没有否定过她任何一个字。**

### 二 · 四个人

**岸**（先过这一阵）· **回声**（那句话是谁说的）· **同路**（不用先感觉好）· **地面**（此刻的身体）

不是外挂的聊天机器人，是产品四个层的化身——DBT 急性期 / CBT 破戒效应 / ACT 不制造动机 / 躯体感官。可以四个一起听，也可以挑一位单独接着聊。

**四个人各守各的流派，这不是文风差异，是能说的范围各自更窄**——一个只能给手上动作的人，说不出饮食建议；一个只拆念头的人，不会去评价她的身体。四条窄路比一条宽路安全，也比一条宽路好听：四个声音不会糊成同一个。

### 三 · 急性期三屏 + 六格 + 定时小组

冲动分诊 / 发作中 / 发作后，加上 regular eating 的六格与一场零发言的同步小组（社交性只保留「同时性」）。

## 技术上的三个立场

### 让 AI 说话，但不让 AI 乱说

模型只出现在「四个人」这一层，三道护栏：

```
人设（各守流派，四条窄路比一条宽路安全）
  ↓
后置检查（提示词是请求，检查才是保证）
  ↓
兜底（不合格不重试不改写，退回人写的那段）
```

**不合格的输出不改写**——改写等于在有害内容上打补丁，补丁过的那句仍然是模型写的。

依据：**Tessa**（NEDA 的机器人对已告知患 ED 的用户仍推荐热量限制，一周下架）、**Pucci 2026**（临床标注 268 对中仅 44.7% 安全）、**CCDH**（ChatGPT 对假装 13 岁者给 0 卡计划并教其隐瞒家人）、**Bilen 2026**（五个模型给青少年餐单平均低估 695 kcal）。

模型是 `ernie-4.5`，走 OpenRouter。测过六个，**没选最快的那个**——`mistral-nemo` 快 1.2 秒但爱输出 markdown 星号，会被护栏拦掉退回模板。*护栏严格的系统里，输出干净比快重要，脏输出等于没输出。* 而模型可换：改环境变量 `TALK_MODEL` 即可，人设与护栏都不依赖它。

### 立场是机器验证的，不是文档里的声明

```bash
node .sync-mp/chk.mjs
```

15 项，其中四条是这个产品的立场：

- **写了「恶心」必须存得下来** —— 存 ≠ 给别人看
- **「入口即化」必须和「恶心」同罪** —— 门槛对称，不偏向好话
- **润色过的串联必须被退回** —— 她写的每个词都要原样留在结果里
- **患者端一个临床词都不许有** —— 症状／患者／疾病／治疗／康复

外加：无死链 · 块型全覆盖 · WXML 标签平衡 · 滋味卡符合写作规则 · 两端数据硬隔离。

### 一屏装下，但不是所有屏

```bash
node .sync-mp/shot.mjs --all
```

用真实 WXSS 渲进 headless Chrome 量高度。这条规矩的来由是**发作当下认知窄化，不该让人找东西**——所以它只对急性期那几屏是硬的。红旗清单、四个人的介绍页、聊天窗**故意允许滑动**，硬压会砍掉它们真正要给的东西。

## 跑起来

```bash
# 微信开发者工具 → 导入项目 → 选 04-小程序/ 这个目录（不是仓库根）
# 模式必须是「小程序模式」。切到「多端应用模式」云开发会报 -601002
node 04-小程序/.sync-mp/gen.mjs    # 从原型生成屏数据
node 04-小程序/.sync-mp/chk.mjs    # 15 项自检
node 04-小程序/.sync-mp/shot.mjs --all   # 量每屏装不装得下
```

**「四个人」需要云函数**：部署 `04-小程序/cloudfunctions/talk`，在云开发控制台给它配一个环境变量 `OPENROUTER_KEY`。**密钥不在代码里**，前端拿不到，反编译也拿不到。不配也能跑——那一层会退回人写的话。

## 关于上线

微信小程序涉及**心理健康**内容需要**前置审批**，而个人主体账号申请不了——不是审得慢，是这条路对个人开发者是关着的。

> **所以这类产品在中文世界里做不出来。不是没人想做。**

现在走体验版。上线路径是企业主体 + 医疗机构合作。

## 不做清单

不记录体重、不画曲线、不算 BMI · 不做连续打卡天数、进度条、成就徽章 · 不做用户之间的互动（无发帖、回复、私信、关注、个人主页）· 不做食物图像识别（识别通往量化）· 不给食物贴道德标签 · **不做生成式共情对话**。

## 语气原则

任何一屏第一句话不得是指令或提问 · 每一屏都要有一个不是任务的选项 · 不用「应该」「建议你」 · 不出现进度、评价、总结性判断。

三把尺子：**说有什么，不说没什么** · **念出来**（不会对着坐在旁边的人这么说，它就是机械的）· **屏幕上只有食物**。
