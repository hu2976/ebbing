## 作品描述

**进食障碍不是失控，是掌控用错了地方。** 她们的自律是全场最强的，只是指向了「少吃」。
掌控欲消灭不了，也不该劝人放手——劝就是评价——只能改道。

一个人对食物的语言最后只剩下数字。她说不出「香」，只能说「多少卡」。
而市面上所有产品都在给她更准的数字。

### 三件别人没做的事

**一 · 我写的滋味**
每天一张滋味卡，她可以从色 / 香 / 味 / 声 / 质地五个角度写下自己记得的样子。
写完，卡面上系统那段话被换成她自己的话。用久了，整本卡都是她写的。

> 这个产品最后会把自己说的话，全部还给你。

门槛不是正能量过滤器，是**「描述 vs 判断」过滤器**，规则对称、不偏向好话：

| 她写 | 结果 |
|---|---|
| 恶心 | 不进公共池——「这是判断，不是味道。」 |
| **入口即化** | **同样不进**，理由一模一样 |
| **臭 / 酸了 / 发苦 / 黏手** | **放行**，那是真实的气味 |

而**存下来、上时间线、上卡面是三个不同的权限**：她写什么都存（永远在她自己手机里），
时间线里全都在（变化要看得见），卡面只放过了门槛的那条。
**产品从头到尾没有否定过她任何一个字。**

**二 · 四个人**
岸（先过这一阵）· 回声（那句话是谁说的）· 同路（不用先感觉好）· 地面（此刻的身体）。
AI 说话，但不让 AI 乱说：人设、护栏、无状态，密钥在云函数环境变量里，前端拿不到。
**不配密钥也能跑**——那一层会退回人写的语料。

**三 · 急性期三屏 + 六格 + 定时小组**

## 技术上的立场

**立场是机器验证的，不是文档里的声明。** `chk.mjs` 16 项自检，其中一条是硬规则：
**患者端不许出现任何临床词**（症状 / 患者 / 病人 / 疾病 / 障碍 / 治疗 / 康复 / 诊断），
自动扫全部 84 屏和每日轮换池。这个产品的第一条原则是不预设她是谁。

文案有唯一源、视觉有唯一源，`data/` 与 `.wxss` 全链路生成，不手抄。

```bash
# 微信开发者工具 → 导入项目 → 选仓库根目录（miniprogramRoot 已指向 04-小程序/）
# 模式选「小程序模式」

node 04-小程序/.sync-mp/chk.mjs         # 16 项自检，clone 下来就能跑

# gen.mjs 与 shot.mjs 是作者本机的构建工具，不在提交仓库的运行链上：
# 前者的源是工作仓的原型与设计画布，后者需要 macOS 与本机 Chrome。
# data/*.js 与 tokens.wxss 是生成物，已在仓库里，导入即可运行。
```

**「四个人」需要云函数**：部署 `04-小程序/cloudfunctions/talk`，
在云开发控制台给它配环境变量 `OPENROUTER_KEY`，并把该函数的执行超时从平台默认的 3 秒改大（四个人是并发调用）。密钥不在代码里，反编译也拿不到。
